---
title: Installed files
description: Every file skillpack writes into a project, which ones are committed, and how it protects your edits.
---

`skillpack` installs into the current project only. It writes two kinds of output:

| Output | Depends on | Committed |
|---|---|---|
| Rendered skills | The pack commit and `skillpack.json` | **Yes.** They're the same on every machine. |
| Generated agents | The above, plus your `skillpack.models.json` | **No.** Each engineer generates their own. |

## Project files

| Path | Committed | What it is |
|---|---|---|
| `skillpack.json` | Yes | [Selection config](/user/config/): packs, versions, skills and agent bindings |
| `skillpack-lock.json` | Yes | [Lock file](/user/lock-file/): commits and skill hashes |
| `.agents/skills/<scope>-<name>/` | Yes | Rendered skills |
| `skillpack.models.json` | No | [Models file](/user/models/): the models on your machine |
| `.opencode/agents/<scope>-<agent>.md` | No | Generated OpenCode agents |
| `.codex/agents/<scope>-<agent>.toml` | No | Generated Codex agents |

After `add`, `skillpack` prints which paths to commit.

## Rendered skills

Each skill is installed as a folder in `.agents/skills/`, which both OpenCode and Codex read:

```text
.agents/skills/
  morovid-plan-code/
    SKILL.md
    references/planning-guide.md
  morovid-review/
    SKILL.md
```

- The folder name and the `name` in `SKILL.md` are `<scope>-<name>`, so two packs can both ship `implement`.
- The whole skill folder is copied, including `references/`, `assets/` and scripts. `skillpack` never runs them.
- Placeholders are replaced with the agents you chose, so the skill names the right agent in each harness.

## Generated agents

For each agent bound to `generate`, `skillpack` writes one file per harness:

```text
.opencode/agents/morovid-author.md
.codex/agents/morovid-author.toml
```

Both use the same ID, `<scope>-<agent>`, always in kebab case. Agents with `mode: primary` are generated as ordinary subagents in Codex, which has no primary agents.

Each file starts with a header:

```toml title=".codex/agents/morovid-author.toml"
# generated by skillpack from https://github.com/morovid/skills@v1.0.0 src/agents/author/ — do not edit; change with `skillpack configure`
# binding: generate gpt-6.2-sol/high
# hash: sha256-9c41…
name = "morovid-author"
…
```

The header says where the file came from and marks it as owned by `skillpack`. The `hash` covers everything below the header, so a hand edit is detected without any other record.

Agents contain concrete models from your `skillpack.models.json`, so they differ between engineers and aren't committed. After cloning a project, run:

```sh
npx @morovid/skillpack install
```

It matches models on your machine, writes `skillpack.models.json` and generates the agents for the harnesses it finds on your machine. Run it again after pulling a change to `skillpack.json`; `skillpack doctor` reports agents that are missing or out of date.

Your own agents in `.opencode/agents/` and `.codex/agents/` are never touched.

## What goes into git

`skillpack` keeps its local files out of git with a block in `.git/info/exclude`, the repository's own ignore file that isn't committed:

```text title=".git/info/exclude"
# >>> skillpack (managed; do not edit)
/skillpack.models.json
/.opencode/agents/morovid-author.md
/.codex/agents/morovid-author.toml
/.codex/agents/morovid-scout.toml
# <<< skillpack
```

- The block lists exact paths, not patterns, so your own agents in the same folders are still committed as usual.
- `add`, `install`, `sync`, `configure`, `update`, `upgrade` and `remove` keep the block up to date.
- `.gitignore` is never changed, and teammates who haven't installed anything see no new rules.
- All worktrees of a repository share one exclude file. Paths are added when a file is generated and removed only by `skillpack remove`, so one worktree's changes don't un-ignore another's agents.
- Outside a git repository, `skillpack` prints the paths to ignore instead.

If git already tracks one of these files, for example because it was committed before, the exclude has no effect. `skillpack doctor` warns about it and suggests `git rm --cached <path>`.

## Protecting your edits

`skillpack` only changes or deletes files it owns and that haven't been edited:

| File | Owned when | Edited when |
|---|---|---|
| Skill folder | It's listed in `skillpack-lock.json` | Its hash differs from the lock file |
| Agent file | Its header names the pack | Its content differs from the `hash` in its header |

Anything else is listed and kept. `--force` overwrites or deletes it anyway. The exception is `install`, which restores edited skill folders to match the lock file, like `pnpm install`; it lists them, and the edits can be recovered from git. `--dry-run` shows every file and config change before anything is written. If a command fails part way, the project is left unchanged.

## Harness settings

Some agent setups need a harness setting, such as Codex `[agents] max_concurrent_threads_per_session`. `skillpack` prints these as snippets for you to add. It never edits harness config files.

## Skills installed by `npx skills`

A pack's plain build can also be installed with `npx skills`, under unprefixed names such as `implement`. `skillpack` leaves those folders alone: they aren't in its lock file. If the same pack is installed both ways, the skills load twice (`implement` and `morovid-implement`), so `skillpack` warns and suggests `npx skills remove <names>`. It never removes them itself.

## Removing a pack

`skillpack remove <pack>` deletes the pack's unedited skill folders and agent files, and removes the pack from `skillpack.json`, `skillpack.models.json`, `skillpack-lock.json` and `.git/info/exclude`. Edited files are listed and kept unless you pass `--force`.
